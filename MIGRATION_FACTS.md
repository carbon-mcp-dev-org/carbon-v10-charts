## React version compatibility

`@carbon/react@^1.x` peer dependency (verified against the installed package):
```
react: "^16.8.6 || ^17.0.1 || ^18.2.0 || ^19.0.0"
react-dom: "^16.8.6 || ^17.0.1 || ^18.2.0 || ^19.0.0"
```

**React 16.8.6+ IS supported by Carbon v11.** You do NOT need to upgrade to
React 17 or 18. If you see a claim that "Carbon v11 requires React 17+",
that claim is **incorrect** for `@carbon/react@^1.x`. Verify the peer-dep
range yourself with `npm view @carbon/react peerDependencies`.

This migration kept React at 16.13.1, which is compatible.

## Dependency-only changes (what the migration did NOT touch)

The Carbon Migrate v10 → v11 migration class touches Carbon-related deps
and source code only. It did NOT modify:

- React (kept at 16.13.1)
- react-router-dom (kept at 5.2.0)
- Build tools (TypeScript 3.9.7, react-scripts 3.4.3)
- Test framework (jest, react-scripts test)
- Application-runtime deps (lodash, papaparse, etc.)

If `npm install` fails with ERESOLVE for a non-Carbon package, that conflict
is **pre-existing** in this project, not caused by the migration. Common
example: `ts-jest@26` requires `jest@26+` but the project pins `jest@24`;
this conflict exists in the v10 codebase too.
